# Полный разговор Home Butler через Алису

## Что получится

После однократной фразы «Алиса, запусти навык Домашний дворецкий» колонка открывает одну разговорную сессию. Дальше можно задавать любые вопросы, продолжать тему и отдавать разрешённые команды Home Assistant без отдельных сценариев в приложении Яндекса.

Распознавание голоса и озвучивание выполняет Алиса. Сама модель `home-butler`, память текущего разговора, чтение Home Assistant и безопасные команды устройствам остаются локальными.

## Что уже готово

- локальный full-dialog шлюз на `127.0.0.1:8765`;
- память нескольких реплик и открытая сессия `end_session:false`;
- защита от повторного выполнения одной команды;
- случайный секрет в адресе, проверка ID навыка и опциональная проверка владельца;
- запрет произвольных HA service calls: только существующие switch/light/button границы;
- постоянный прогрев модели на RX 6600 XT;
- голосовой профиль: 2048 токенов контекста, ответ до 64 токенов;
- все активные обращения к локальной модели используют один прогретый
  `home-butler` runner с context 2048 и `keep_alive=24h`, поэтому проверки HA и
  ресурсов больше не выгружают голосовую модель;
- опубликованный приватный навык уже достиг локального gateway с физической
  колонки; первоначальный fail-closed ответ выявил и позволил исправить
  ошибочную маршрутизацию вопросов о возможностях;
- живое доказательство памяти после исправления: модель запомнила «Аврора» и
  вернула это слово в следующей реплике; задержки 1,220 и 0,879 секунды;
- пять полных запросов в формате Yandex Dialogs прошли 5/5 за 1,524–2,722 с;
- голосовое чтение Home Assistant получает тот же root-managed credential
  через точный allowlist для `home-butler-alice-skill.service`; варианты
  произношения «хому асистанс», «хоум ассистанс» и «хаос» проходят 3/3 за
  1,633–1,749 с и возвращают реальные counts без service calls;
- после tool-call второй проход той же локальной LLM формулирует естественный
  доклад из bounded counts; защитный валидатор исправляет пропущенный факт, но
  никогда не пропускает изменённые числа. Follow-up «что это значит?» и «скажи
  проще» идут в свободную модель с памятью, а не в сценарий;
- бытовые light intents отделены от обычной речи: «включи свет» остаётся HA
  control, а разговор о солнечном свете или звёздах не вызывает умный дом;
  пятиходовый разговор о космосе прошёл 5/5 с памятью темы;
- живой полный HA-запрос в формате Yandex Dialogs прошёл за 2,636 секунды:
  модель сама выбрала read-only `ha_get_snapshot`, получила настоящий
  очищенный факт, а итоговый ответ подтвердил `service_calls=0`;
- ngrok 3.39.8 уже установлен, авторизован и имеет постоянный HTTPS-домен `dancing-hull-numerous.ngrok-free.dev`.
- безопасный режим первичной привязки уже включён и проверен через публичный
  HTTPS-адрес; до получения запроса Яндекса он не вызывает модель и Home
  Assistant.
- root-only наблюдатель привязки active/enabled: первый валидный private claim
  автоматически закрепляет skill/user identity, перезапускает только голосовой
  шлюз и удаляет временный claim лишь после успешного старта; ошибки ограничены
  тремя повторами за пять минут. Перед перезапуском выдерживается три секунды,
  чтобы первый ответ проверки успел вернуться Яндексу.

## Первичная настройка (уже выполнена)

1. Войти в [консоль Яндекс Диалогов](https://dialogs.yandex.ru/developer/).
2. Создать «Навык в Алисе» с именем из двух слов, например «Домашний дворецкий».
3. Выбрать приватный доступ. Сценарии умного дома не создавать.
4. Загрузить готовую квадратную иконку
   `/root/Jarvis/home-butler/assets/alice-skill-icon.png` (точно 224×224 PNG).
5. Открыть локальный приватный файл
   `/root/Jarvis/home-butler/secrets/alice-webhook-url.txt` и скопировать из
   него единственную строку целиком. Это уже готовый закрытый webhook.
6. Вставить адрес в поле Webhook и запустить проверку/сохранение. Первый запрос
   Яндекса сам безопасно передаст ID навыка; вручную искать его не нужно.
7. Подождать несколько секунд. Home Butler сам проверит полученный ID, закрепит
   его и переключит gateway из режима привязки в GPU-backed полный диалог.
   Проверить результат можно локальной командой `/голос`: строка «Привязка»
   должна сообщить, что приватный навык закреплён.
8. Опубликовать навык с приватным доступом и на колонке сказать:
   «Алиса, запусти навык Домашний дворецкий».

Токены, пароль Яндекса, ID навыка и содержимое webhook-файла в чат присылать
не нужно. Сообщить в Codex о публикации потребуется только для совместного
живого теста колонки, а не для технической фиксации identity.

## Безопасная замена засвеченного Webhook

После того как закрытая часть первого Webhook попала на скриншот, подготовлена
смена без простоя. Шлюз временно принимает старый и новый закрытые адреса, но
старый не будет удалён до доказанного корректного запроса Яндекса по новому.

1. Сначала закончить повторный живой тест колонки по уже указанному адресу.
2. В WSL выполнить `./scripts/copy-alice-webhook-url.sh`. Новый root-only адрес
   будет скопирован прямо в буфер обмена Windows без вывода на экран.
3. Заменить Webhook URL в настройках приватного навыка, сохранить и выполнить
   один тестовый запрос.
4. Подождать 5–20 секунд. Root-only auto-finalizer проверит authenticated
   marker, переключит primary с rollback-контролем и удалит старый адрес.
   Дополнительная серверная команда не требуется. При желании итог можно
   проверить через `sudo ./scripts/rotate-alice-webhook.py --status`: ожидается
   `idle`.

Команды `--stage`, `--commit` и `--abort` никогда не печатают секрет. При
ошибке запуска шлюза изменение откатывается; без прошедшего identity-check
commit запрещён. Рабочий
`home-butler-alice-rotation-finalize.path` повторяет эту проверку автоматически
и не запускает service до появления корректного marker.

Текущий безопасный статус можно посмотреть обычной фразой `/голос` в локальном
чате. Он показывает gateway/tunnel, режим привязки и доступность колонок, но не
показывает секреты или внутренние ID.

## Проверка

В живом тесте должны пройти подряд:

1. «Кто ты и что ты умеешь?»
2. «Продолжи предыдущую мысль короче» — доказательство памяти сессии.
3. «Что сейчас с Home Assistant?» — свежие локальные данные.
4. «Включи свет в коридоре» — модель должна выбрать только `switch.kavidor_switch_1`, выполнить один разрешённый вызов и подтвердить состояние повторным GET.
5. «Закрой навык» — корректное завершение сессии.

## Честные ограничения

- Первая фраза всегда открывает навык по имени. Это требование Яндекса, а не сценарий на каждую команду.
- Сервер навыка обязан ответить Алисе целиком за 4,5 секунды. Поэтому устные ответы короче терминальных.
- Голосовое чтение HA использует короткое двухшаговое доказательство модели и
  точный детерминированный вывод snapshot; длинный диагностический отчёт
  остаётся для локального чата.
- Если GPU-модель холодная или недоступна, голосовой шлюз не запускается в медленном CPU-режиме и не рискует выполнить запоздалую команду.
- До успешного теста на физической колонке контур нельзя считать полностью завершённым.
