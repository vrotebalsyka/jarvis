# Одноразовая настройка восстановления Home Assistant

## Что уже готово

На основном ПК создан отдельный ключ и безопасный локальный worker. Он не даёт
модели терминал, пароль, Docker socket или обычный SSH. Канал может выполнить
только одну фиксированную операцию: проверить контейнер Home Assistant и, если
его веб-интерфейс действительно не отвечает, запустить/перезапустить именно
этот контейнер с последующей проверкой.

Автоматический таймер намеренно выключен до завершения этой инструкции.

## Что требуется от владельца

Нужен административный вход на Ubuntu-компьютер `192.168.1.127`, где запущен
Home Assistant. Это отдельное устройство в локальной сети, не текущий WSL.

SSH-пользователь подтверждён: `victor`. Пароль в чат отправлять не надо.
Запустите в обычном Ubuntu WSL терминале одну команду:

```bash
cd /root/Jarvis/home-butler
./scripts/bootstrap-ha-recovery-victor.sh
```

Сначала OpenSSH попросит пароль `victor`, затем `sudo` может попросить его ещё
раз. Вводимые символы не отображаются — это нормально. Пароль читает только
OpenSSH/sudo; launcher его не принимает, не журналирует и не сохраняет.

Повторный запуск безопасен: если recovery identity уже существует, launcher
переходит в строгий режим ремонта, заново проверяет её тип, группы, файлы,
shadow и эффективную политику sshd. После этого он сам требует точный ответ
`status=healthy_no_action`; без такого ответа успех не печатается.

Файл в `/etc/ssh/authorized_keys` остаётся root-owned и неизменяемым для
recovery-пользователя, но имеет режим `0644`: OpenSSH читает этот публичный ключ
уже под UID целевого пользователя. Секретный приватный ключ остаётся только в
WSL с режимом `0600` и на HA-хост никогда не передаётся.

Если вы уже открыли терминал прямо на том Ubuntu-компьютере, достаточно
сообщить: «я в терминале 192.168.1.127 под администратором». Codex даст одну
команду установки или продолжит сам через ваш открытый терминал.

## Что сделает установка

1. Проверит Ubuntu, Docker и ровно один контейнер с меткой
   `io.hass.type=core`, официальным образом Home Assistant и каталогом
   `/config`.
2. Создаст отдельного пользователя `homebutler-recovery` без пароля.
3. Разрешит этому ключу только принудительную фиксированную команду и только из
   сети `192.168.1.0/24`; shell, TTY, forwarding и произвольные команды будут
   запрещены.
4. Разрешит через `sudo` только один root-wrapper без аргументов.
5. Проверит конфигурации `sudo` и SSH перед перезагрузкой SSH-службы.
6. Не будет перезапускать Home Assistant во время установки.
7. Выполнит read-only аудит способа запуска HA Container (Docker Compose или
   ручной запуск), не экспортируя environment/secrets, и сохранит результат
   локально с правами `0600` для подготовки проверяемого обновления Core.

## После установки

Проверка выполнена 4 августа 2026 года: получен `healthy_no_action`, то есть
ноль перезапусков. `home-butler-out-of-band-recovery.timer` включён и активен;
worker отдельно проверен на пути `candidates=0` без открытия SSH и без действий.

При плановом обслуживании на Ubuntu-хосте файл
`/run/homebutler-ha-maintenance.lock` временно запрещает автоматический
перезапуск.
