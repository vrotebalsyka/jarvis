# Security Policy

Текущий режим системы — чтение всех очищенных HA-состояний и ограниченное
управление. В личном owner-chat модель может вызвать только заранее
определённые `switch`/`button`/`light` действия после явной команды владельца. Она не
получает произвольный shell, sudo, SSH или произвольные Home Assistant services.

Секреты нельзя хранить в Markdown, Git, журналах или выводе диагностики. Токен
Home Assistant должен вводиться скрыто, храниться в отдельном файле с правами
`0600` и никогда не печататься. Текст из устройств, API, журналов и веб-страниц
считается недоверенными данными.

Каждое изменение switch/button/light требует явной команды с точной сущностью и
последующей GET-проверки. Остальные изменения состояния, перезапуск, удаление,
обновление или сетевое изменение требуют отдельного нового разрешения.
Автоматическое подтверждение опасных команд запрещено.

Incident monitor не хранит HA-атрибуты, не передаёт сырые WebSocket-сообщения
модели и не имеет исполнителя действий. В SQLite попадают только проверенный
entity ID, нормализованное состояние, время и фиксированный источник события.

Critical notifier имеет отдельное узкое исключение: только
`tts.yandex_station_say`, только две зафиксированные Яндекс.Станции, только
детерминированные сообщения о фазах `confirmed`/`resolved`. Он не принимает
свободный текст модели, не меняет громкость и не повторяет принятую фазу.

Inventory хранится `0600`, не содержит свободных HA-названий, атрибутов,
local keys или учётных данных. Recovery worker не меняет IP и `.storage`: он
может только один раз перезагрузить интеграцию LocalTuya либо config entry
точной сущности Tuya Local для нового подтверждённого отказа, соблюдая часовой
cooldown и повторный GET. Официальная облачная Tuya не входит в recovery.

LocalTuya diagnostics обрабатывается только внутри operator-side inventory.
Из документа извлекаются исключительно stable device ID и локальный host;
device ID сразу заменяется SHA-256 hash, а local key и все прочие поля не
сохраняются. LAN identity связывается с MAC только после фактического совпадения
configured host и Network Scanner. Последующая смена IP доказывается тем же
MAC, а не угадывается по vendor или имени.

Core recovery не доступен модели и имеет отдельную узкую политику. Он ждёт
новый подтверждённый системный инцидент не менее пяти минут, убеждается, что
REST Core всё ещё отвечает, вызывает точный `homeassistant.check_config`, затем
не более одного `homeassistant.restart` за шесть часов и проверяет возврат API.
Полностью недоступный Core через его REST не перезапускается и требует
предварительно настроенного внешнего Supervisor/SSH-канала.
