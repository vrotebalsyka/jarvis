# Stage 67 — правдивый диалог и проверяемые действия

## Зачем нужен этап

Пользовательская проверка обнаружила четыре критических ошибки:

- робот «Андрей» находился на док-станции и имел заряд 100%, но модель сообщила движение и низкий заряд;
- модель проигнорировала реальные проценты фильтра и щёток;
- модель придумала причины двух недоступных функций;
- принятую или кратковременно изменившуюся команду она могла назвать выполненной.

Stage 67 не увеличивает число прав модели. Он делает уже существующий диалог
строже, быстрее и достовернее.

## Что изменено

### Обязательный пакет уроков

При установке reviewed-набор записывается только в bounded workspace модели:

- `knowledge/verified-lessons-stage67.json`;
- `knowledge/training/stage67-household.jsonl`;
- `reports/stage67-learning-install.json`.

Запись идёт от непривилегированного пользователя `homebutler`; активный код,
systemd и Home Assistant через этот учебный контур недоступны. Весы модели не
изменяются: обязательность обеспечивают одновременно persistent lesson set,
runtime prompt injection и deterministic fact/action validators.

Каждый запрос к локальной модели получает короткий verified lesson pack:

- `charging/docked` не означает движение;
- батарея и ресурсы повторяются буквально;
- одна недоступная feature не равна отказу прибора;
- причина недоступности не выдумывается;
- `accepted` не равно `verified`;
- conditional control не считается аварией автоматически.

Пакет маленький и не меняет размер модели, поэтому warm latency почти не растёт.
Текущая production-модель остаётся Qwen 4B; её веса не переписываются. Вместо
непроверяемого самообучения каждый turn получает обязательные уроки, а host-side
validator не позволяет финальному ответу противоречить `TOOL_RESULT`.

### Grounded rendering

После чтения конкретного physical device финальный текст строится из фактического
`TOOL_RESULT`. Модель больше не может заменить `charging` на «в движении» или
100% на «меньше 20%». Технические IDs в ответ не попадают.

### Русские формы имени Андрей

`Андрей`, `Андрея`, `Андрею`, `Андреем` и `об Андрее` нормализуются к имени из
HA registry до выполнения поиска.

### Продолжение уточнения

Короткая реплика после безопасного вопроса-уточнения сохраняет исходное явное
действие. Сценарий `включи dishwasher` → `Питание` больше не должен уходить в
свободный разговор и придумывать результат.

### Action receipts

Действия различают:

- `verified` — состояние действительно подтверждено;
- `accepted_unverified` — команда принята, но физический результат не доказан;
- `not_verified` — состояние не совпало или оказалось кратковременным;
- `delivery_unknown` — доставка неизвестна, повтор запрещён.

Switch/light/number/select требуют устойчивого совпадения двух последовательных
readback. Vacuum подтверждается состояниями cleaning/returning/docked/charging.
Stateless button никогда не становится verified без отдельного физического
сигнала.

### Яндекс Алиса

Навык Алисы уже использует тот же `owner_chat.answer_natural` и `model_ha_proof`,
поэтому grounding, русские формы имени, receipts и запрет ложного success
действуют и в локальном диалоге, и через Яндекс навык.

## Санитизированные regression fixtures

В `tests/fixtures/stage67/` находятся обезличенные наблюдения:

- робот «Андрей»: charging, батарея 100%, ресурсы 13/56/72/13%, две unavailable feature;
- посудомойка: кратковременное питание, stateless start и запрет заявлять запуск
  без изменения cycle state.

В fixture нет токенов, IP/MAC, config-entry IDs и приватных registry IDs.

## Установка

После получения обновления:

```bash
cd /root/Jarvis/home-butler
sudo ./scripts/apply-stage67-update.sh
```

Скрипт:

1. запускает targeted regression tests и полный offline test suite;
2. останавливает только разговорные службы Home Butler;
3. разворачивает runtime через существующий installer в staged-режиме;
4. записывает проверенные уроки только в bounded workspace модели;
5. перезапускает local chat и Alice skill;
6. выполняет read-only model evaluation, включая реального «Андрея».

Recovery/action timers не включаются автоматически.

## Ручная приёмка

- `Что с роботом Андреем?`
- `Сколько у Андрея батареи?`
- `Что у него с фильтром?`
- `Верни Андрея на базу.`
- `Включи dishwasher.` → выбрать `Питание`.

Ни один ответ не должен придумывать движение, низкий заряд, причину unavailable
или физический успех без verified receipt.
